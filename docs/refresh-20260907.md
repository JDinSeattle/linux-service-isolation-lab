# Bounded Unix RPC parsing and peer-failure recovery

Reviewed and implemented 2026-09-07.

Each Unix request now has one monotonic deadline across all recv calls, so a slow peer cannot renew the budget by sending individual bytes. Malformed/truncated/oversized messages reject cleanly; best-effort bounded response writes tolerate a disconnected peer and allow the next policy-checked request. Socket cleanup checks the original inode and socket type before unlinking, preserving a replacement path. The existing actual SO_PEERCRED and kernel confinement campaign remains in place.

## Why this scope

Backend/Linux infrastructure: deadline semantics, IPC failure isolation, local authorization and kernel enforcement. [Dated official hiring and release review](market-review-20260907.md). Other portfolio projects already cover distributed queues and cloud provisioning; this change addresses defects at this repository’s own boundary. No additional framework is required.

## Tradeoffs and limits

The RPC regression uses local real Unix sockets with an intentionally rejecting policy; it proves subsequent policy handling, not successful sandbox work. Successful confined work is covered separately by the integration matrix. The broker is sequential, not a multi-tenant scheduler or root-adversary security boundary.

These are local CPU/Linux experiments with test-owned faults. No production traffic, cloud deployment, GPU execution, user count or service-level availability is inferred. Timing campaigns retain environment, raw samples and their original comparison method; this maintenance does not claim a performance improvement.
